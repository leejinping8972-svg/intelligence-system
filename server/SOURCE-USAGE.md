# 数据源消耗看板

功能基线：testing `97486854d3ab394e4f83fd3dd58c1e07db2499b4`。本功能不自动执行业务报告、不购买服务、不修改正式配置。

## 页面与配置

- `/settings` 展示 18 个来源的服务介绍、接入状态、今日/累计消耗、剩余额度及快照时间。积分、调用、请求与 token 分别统计，不相加。
- 卡片打开配置弹窗，复用 Semrush、Sorftime、Firecrawl、YouTube、ScrapeCreators 和 AI 现有加密配置。新增 Brave Key 编辑保留原研究访问码等其他凭据。
- Semrush 标准余额与 Firecrawl `/v2/team/credit-usage` 为专用账户查询。首次进入时，对已配置且没有余额的支持来源尝试获取；弹窗可手动刷新。Semrush MCP/v4 账号未必有标准余额权限，失败可手动填写。ScrapeCreators 复用已有检测时记录的余额，不自动执行可能扣费的检测。
- 手动登记支持剩余额度、总额度、到期日期及优先使用手动值。自动查询失败保留旧快照；密钥变更后旧自动快照失效。余额是账户快照，不使用本地日志推算完整账户账单。

## 消耗明细与时间

- 读取研究请求原始 journal、竞品监控原始 journal、公共内容步骤与独立站采集事件。只投影记账元数据，不向前端返回原始业务响应、密钥或加密配置。
- 明细支持日期、来源、扣费状态、任务名称/编号/环节查询及每页 25 条分页。点击任务编号筛选该任务的全部来源消耗。
- 按请求开始时间的北京时间归日。旧研究记录没有请求时间，保留累计值并放入“历史未定日期”，不借用任务创建时间。来源不明的历史请求列为“来源待核验”。
- 缓存不重复累计。已确认零、缺失、失败、进行中及部分确认分别处理；未知扣费不会按零显示。有缺口的已确认小计显示 `+`。
- 研究 journal 新增内部 `requestUsage`，保存来源、操作与开始时间；不改变采集公开返回结构。公共内容保存步骤时间和扣费元数据；官网/托管采集使用独立事件预留后结算。
- 每日公共情报采集子进程通过固定域名白名单记录每次实际尝试和来源环节，查询参数和凭据不入账。只在专用采集子进程启用，不修改 API 进程的全局 fetch。
- 公共接口统计请求数；YouTube 未返回真实配额扣减的请求保留“待确认”。AI 仅累计返回的 token 用量，未配置模型价格时不估算金额。旧日志/外部账户其他调用不保证完整覆盖。

## 存储与权限

- `provider_configs/source-usage:quota:<id>` 保存非敏感额度登记；`workspace_documents/source-usage:event:<hash>` 保存独立请求事件。沿用现有双库表及备份/迁移机制，无新业务表或依赖。
- 所有新查询/写入接口要求管理员。统计查询本身不访问第三方；账户余额更新单独触发。不修改请求重试、队列预算、取消与未知收费停止规则。
- 接口：`server_source_usage`、`server_source_quota_save`、`server_source_quota_refresh`、`server_source_credential_save`（仅 Brave）。

## 验证与边界

### 2026-10-28 超时修复

- 监控 journal 采用 JSON 类型保真的单次字段提取，分批读取记账元数据；派生结果压缩保存在 `workspace_documents/read:source-usage:monitor:v1`。后续按原记录 revision 增量更新并移除已删除项，保留原始 journal、来源归属及未知扣费含义。
- 进程内 15 秒结果缓存合并并发读取；手动刷新绕过已完成结果缓存，已有后台读取仍共享。读取超过 2 秒时 `server_source_usage` 返回 `{loading:true,retryAfterMs:2000}`，前端等待后继续查询，不延长单次请求超时。失败保留短暂错误供轮询显示，手动重试可立即重新读取。
- 分批中断只保存可重建的已完成缓存，下次继续；不返回部分记录的统计。缓存损坏自动重建，缓存写入失败不阻止完整结果返回。统计请求不调用第三方、不刷新额度，不新增表、结构或业务数据迁移。
- 首次加载取消无条件二次查询；翻页复用当前结果，手动刷新明确读取最新记录，离开页面停止轮询。初次失败显示“未获取”，已有结果刷新失败保留原结果，不以占位零冒充真实消耗。
- 正式 MySQL 只读验证：100 条相同原记录的新旧会计投影完全相等；6,773 条监控记录首次整理约 143 秒，模拟持久缓存复用约 1.6 秒、原 journal 投影数为 0。此项只测监控读取，不代表整页时间；验证缓存仅在内存中保存，正式缓存需部署后生成。
- 功能专项 21 项 Node/PGlite 测试及完整 Web 类型检查、独立 server/history 前端构建、服务端专项 ESLint/diff 检查通过。测试覆盖并发/失效/失败恢复、类型与零值、持久缓存重用/修订/删除/损坏、分批中断及原记录和敏感信息保护。真实 MySQL 上 6 组合成边界数据的新旧投影一致，未写业务表。
- Edge 合成验收覆盖加载占位、自动轮询、首次只加载一次、翻页与手动刷新、失败重试及保留旧结果、离开停止/返回恢复、390/320px 宽度；页面错误和全局横向溢出为 0。不将上述模拟和只读验证记作正式上线确认。

- Node/PGlite 专项及相关采集/内容/额度回归共 95 项通过、0 失败，覆盖日界、历史未定日期、单位分离、任务/环节、缓存/未知/部分确认、额度、权限、脱敏 SQL、公共采集记录及 Brave 凭据保留。
