# 新品销量证据与限定候选复核

详情合并按 `resourceRaw` 字段保留已有观察；缺少/null 的 `salesEvidence`
不能清空列表证据。明确返回的新销量（包括 0）作为完整观察替换旧值，不把旧
provider/时间拼入新观察。保留配送方式等其他原始证据。

`reviewHealthCandidate` 仅供有明确范围的运维复核，不是自动分类入口：

- 校验原始商品和候选的 ID、来源商品编号及市场一致后，才恢复缺失的销量证据。
- 人工分类必须注明负责人和理由，所有引用继续通过原有连续原文检查；不得
  把人工结论写回来源请求或伪装为模型响应。
- 保留原冻结上架窗口、正销量要求和条件粉剂规则。销量冲突保留双方观察；
  最新详情为 0 时不回退为列表正数，明确复核后按正销量要求排除。
- 无法从现有原文确认的分类继续 pending，不为清零而放行。

限定恢复在正式环境执行前必须保存任务、候选和已有商品前值，确认任务已经
停止、无结果未知请求；获取任务行锁，保留已成功请求和历史错误。应用可重复
运行，按原商品 ID 入库并只在检查点未包含该 ID 时增加计数。复核轨迹应保留
此前候选判定和原始请求步骤；不得重放采集、改计划或变更冻结时间。

本功能自测使用合成资料。生产 9 件商品的原文、复核清单及回执仅保存在忽略
的本机证据目录和服务器受限目录，不进入 Git。
