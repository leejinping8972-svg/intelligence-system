# 公共内容阅读与历史补全

基线：testing `c9f17fa2e4d20743d853103d040eee5677032acd`。本功能不更改共享 testing，不部署正式版本。

## 阅读布局

- `PublicContentDrawer.vue` 独立负责标题、正文/描述、视频预览、字幕、来源和关联区域。单一主标题，正文分段阅读，来源与关联置于侧栏；900px 以下折叠为单列阅读，580px 以下侧栏也单列。
- 使用现有后台字体与颜色变量；固定底部保留来源、收藏、保存操作。收藏或轮询不会清空未保存的关联草稿。
- YouTube 默认显示封面或轻量预览按钮，点击才挂载播放器，保留加载失败/原平台入口。隔离样例不证明真实视频可播放。
- 文章沿用官方全文章节、表格和图片组件；搜索摘要缺失但全文存在时直接展示正文摘要，不放空摘要占位或重复标题。原文与 AI 整理区分。

## 历史补全

入口：公共内容搜索结果上方的“补全历史详情”。默认仅检查公开详情，字幕/帖子收费读取须勾选。预览显示历史总量、公开步骤、可能收费请求、已复用/已检查和在途数量。

- 新模块 `public-content-enrichment.mjs`；store 新动作 `server_content_history_preview` / `server_content_history_submit`；engine 复用现有公共内容 worker、租约与结果保存。
- 检查所有已保存内容（最多1000条，超过明确报错）；API 可传 itemIds 缩小范围。仅精确查询原文献ID/视频ID/Reddit帖子，不重新搜索关键词，不调用模型。
- Europe PMC core 精确补摘要，沿用现有开放正文采集；YouTube videos.list 读取完整描述；缺失 Reddit selftext 使用已配置 ScrapeCreators。视频字幕只取来源已有字幕，不自动转录音频。
- 同一提交 UUID 绑定范围和收费选项；共享提交租约、在途步骤去重。最多5项活动公共内容任务，单批最多100次收费读取；前端默认不勾选收费。
- 已保存、已检查无内容、失败或计费结果未确认均不自动再次调用。付费来源失败/限流/未配置后停止后续收费步骤，公开正文继续。确需重试须先查原因，不能自动清空状态重放。
- 实际请求和确认扣费分别累计；异常时标记未知扣费，不据“没有正文”推断免费。原文缺失保留明确原因，不用 AI 编造。
- 原子更新保留收藏、产品/关键词关联；摘要改变时清除旧 AI 整理结果，避免把旧摘要分析误当新内容分析。
- 没有数据库迁移、index/runner 路由或依赖变更。发布仍须持有公共内容 runner 锁排空；正式是 MySQL，集成阶段需覆盖其兼容 SQL/事务，不以 PGlite 代替 MySQL 验证。
