# Semrush 已记录消耗积分

设置页用「系统已记录消耗积分」替换账户余额。管理员打开页面或手动刷新时，`server_semrush_usage` 只查询本地数据库；不读取/解密 Key，不发 Semrush 请求，不修改队列，不重新执行采集。

## 统计口径

- 原始 `research_requests` 按 `(job_id, step)` 统计关键词扩词/指标、独立站指标、平台商品请求；平台商品按任务 `checkpoint.work[index].provider` 识别 Semrush，排除 Sorftime。
- `workspace_documents` 中 `competitor:request:*` 的 `semrush:*` 原始请求日志计入关键词监控。两类日志各自只读一次，不累计检查点、关键词指标或提供方缓存文档中的重复值。
- 已完成请求明确返回非负整数 `apiUnits` 才累计；明确 0 保留。缓存命中只计缓存记录数。失败、处理中、缺失/无效扣费不冒充 0，单列「扣费未确认」记录数。平台来源无法识别时单列，不混入 Semrush 总额。
- 旧扩词只存已知扣费小计、没有完整性标记：保留小计，同时标为可能不完整。新扩词保存 `semrushUnknownCharges`，包含未返回扣费与失败子报告；这是不确定性标记，不是推定扣费金额。
- 全部已保存任务、所有市场、包括历史 Key；不是当前 Key 的完整账户账单，不含系统外调用或已删除日志。缺失扣费无法回溯补造，统计可能低于真实消耗。更换 Key 不清零历史记录。
- 刷新失败保留上次数字及时间并提示错误；初次失败显示未知，不显示假 0。没有自动轮询。查询仅投影扣费与来源元数据，不传输整份报告/密钥。

## 集成与验证

新增独立统计模块/单元测试/隔离 SQL 夹具；共用入口仅 `index.mjs` 动作分派、`semrush-config.mjs` 管理员只读动作、`semrush-reports.mjs` 扩词不确定性标记、SemrushSettings 视图、CI专项测试及竞品隔离集成末尾挂载。无依赖或数据库结构迁移，无 worker/锁调整。原标准余额后端保留旧客户端兼容，当前页面不再调用。

本地 Node 回归、PGlite 实际 SQL 集成、web-antd 类型检查和服务器/history 构建已验证；MySQL 使用 CI 中现有隔离竞品集成挂载同一夹具，本功能会话未在真实 MySQL 执行。浏览器使用合成数据验证 1250→1280、失败保留1280、明确0、MCP连接状态不变与390px无横向溢出，未调用真实收费报告。截图数字仅为合成数据。

用户曾反馈只有 v4/MCP Key。先前只读诊断已证实同一Key可连接MCP但标准余额端点HTTP400拒绝，MCP工具未暴露余额入口；用户随后明确改用本地消耗记录。此分支未保留或提交独立余额Key配置，也未导出真实Key。
