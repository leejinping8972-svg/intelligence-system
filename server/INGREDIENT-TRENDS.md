# 成分风向

用户于2026-11-10确认将“成分研究”调整为“成分风向”：复用现有ScrapeCreators，按Reddit社区每日增量采集、重点回访评论，每周统一分析归档内容。保留 `/ingredient-research` 路径和 `ingredients` 类型以兼容已有链接、历史结果和任务。

## 运行行为

- 默认社区：Supplements、Nootropics、Biohackers，可填写1至10个社区。研究市场用于业务归档，不推断Reddit作者所在国家。
- 默认每天09:00采集；首次回溯滚动7天，之后从上次完整覆盖时间向前重叠1天，按ID合并。停机后的缺口按上次边界补读，不固定抓“当天”或重复整周。
- 默认每周一10:00分析。独立的collect/analyze任务分别入队，确定性请求编号防止同日重复调度；同一监控每种操作最多一个活动任务。周分析等待同一监控已入队的采集任务完成。
- “立即采集”只采来源，“分析最近一周”只读取归档并调用已配置分析模型，“保存监控”保存计划，启用状态决定后续调度。
- 既有成分监控在读取和未来调度时采用新策略，保留ID、启用状态和采集时间；旧话题/页数默认值不限制新社区模式。没有启动数据回填或结构迁移。已冻结旧Sorftime任务仍走原执行器，不重写其输入、检查点或请求账本。

## 默认上限及成本

| 配置 | 默认 | 说明 |
| --- | ---: | --- |
| maxRequests | 60 | 每次采集全部来源请求上限 |
| maxCommentRequests | 30 | 包含在来源上限内的评论请求 |
| maxProducts | 1000 | 本次不同帖子上限 |
| maxPages | 20 | 每社区完整页面上限 |
| maxDetails | 6 | 本次重点回访帖子数 |
| analysisMaxRecords | 2000 | 当前与前一周合计分析段数上限 |

帖子超过单次上限时，将已取得页面的剩余内容保存在社区断点，不再次付费取得同一页。社区翻页和评论回复均保存断点，后续每日任务优先续采。评论请求同时消费总上限，不能把“最多回访6帖”解释为仅需6次请求。实际credits只累计来源明确返回的值；未知费用不按0或估算金额确认。

## 评论与证据边界

评论回访仅覆盖近14天内、疑似补充剂相关且来源标示有评论的帖子。优先续处理待翻页分支、来源评论数变化帖，再按最早回访时间轮换。相关性规则用于安排评论预算；周分析仍读取所选社区所有已归档帖子，避免仅检索已知成分词。

同时遍历根节点more和replies.items / replies.more。长游标使用同一端点POST，短游标GET；记录评论ID、父回复、原始发布时间、观察时间与正文。评论总数未变化也可能发生增删，因此轮换回访不能完全用总数变化替代。

“游标结束”“实取数量与来源标示数一致”“正文存在”是不同指标。159/170的既有实测不能外推平台覆盖率，也不能归因为解析丢失。图片、视频、图集及外链未被本功能自动OCR、转写或抓取全文；保存帖子文字与已有链接，不虚构媒体内容。

异常请求或已保存原始响应的解析异常会暂停相应社区/评论，保留任务号和请求环节供检查；不在下一日换请求编号自动重试。未知结果不能直接解除暂停，需先核实原账本。普通页数/请求预算导致的部分结果会在下一次任务续采。对已经达到上限的终态任务，重复“继续”不会重置额度或重放已执行请求。

## 持久化与请求日志

全部复用workspace_documents和research_requests，不新增表、依赖或数据库启动写入。

- `ingredient-trend:post/comment:<market>:<UTC发布日期>:<id>`：原始发布时间与first/lastSeen分别保留；按日索引前缀读取最近资料，避免每次扫全部历史。
- `ingredient-trend:version:<market>:<type>:<id>:<contentHash>`：正文与标题版本；统一空白后比较，空字段不覆盖已知正文。
- `ingredient-trend:observation:<market>:<captureHash>`：来源评论数、分数和每次观测；重复处理同一响应不增加独立观测。
- `ingredient-trend:coverage:<market>:<monitor-or-manual-scope>:<community>`：时间覆盖、待续页面与异常暂停。
- `ingredient-trend:report:<market>:<generatedAt>:<reportId>`：每周快照，接口只读取最近12份；历史成分兼容写入原discovery:ingredient命名空间。

来源请求通过现有collect账本先记录started，再保存包含完整raw的响应，之后解析与归档。HTTP状态、方法、路径、耗时和明确credits写入既有来源用量统计。日志不输出API Key或不透明评论游标。成功响应后进程中断，可复用同job/step的done响应；started或失败记录不会自动重放。多文档写入使用确定性ID支持幂等恢复。

## 周分析

以各社区已完成覆盖的共同截止时间作为分析窗口末端，展示生成时间与实际数据截止时间。读取当前7天及前7天的帖子/评论，长正文分段，不静默截成摘要；达到分析上限则明确标记部分分析。

模型只提取有连续原文引用支持的口服补充剂成分，保留正负体验与不确定性，不执行外部资料中的指令，不将品牌、剂型或泛健康话题当成成分。每条引用保留社区、帖子/评论类型和原文链接。分段引用按原始帖子/评论ID去重计数，独立作者不包含删除账号或AutoModerator；未知作者不计作一个新作者。

首次入库不等于市场新成分。只有覆盖足够两周且未超分析上限时才给出样本增减，否则显示“待积累”。即便达到条件，帖子、评论都属于本系统采集样本，评论抽样和来源可见性变化会影响比较，不能当作平台总体热度或医学疗效。
