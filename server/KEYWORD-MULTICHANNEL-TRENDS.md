# 四平台关键词趋势

## 范围与使用

关键词研究、已入选关键词沿用紧凑列表，分别显示谷歌趋势、TK趋势、INS趋势、FB趋势四列，每列本周、本月、近3个月、近6个月。Google保留一年曲线入口；原30天/半年/一年评分函数和已有评分口径保留，四周期展示使用独立函数。

管理员勾选1至100个真实关键词，在“趋势采集 / 每日监测”选择来源、页数和每日社媒请求上限，确认预算后提交。相同北京时间日期、关键词、来源、检索窗口和页码去重。手动与每日请求共用当日硬上限；Google排队不计入ScrapeCreators请求数。

每日计划默认暂停。管理员启用后，每天在指定北京时间针对所选市场的人工入选关键词运行；执行前重新核对关键词身份和入选状态。每日稳定轮转分配预算；未覆盖步骤显示未执行，不声称覆盖全部关键词。暂停停止尚未开始的定时步骤，手动已提交任务继续；旧日期待执行步骤不自动补跑。当天已经完成、失败或未知的检索不会因重复提交而自动重放；调整来源/页数等计划主要用于后续日期。Google任务沿用原监控与任务页面的取消/重试流程。

## 数据口径

- Google：原始Google Trends 0–100相对热度的日数加权均值，不是搜索量。原始UTC日历日期；本周从周一、本月从1日起，到采集时的最后完整日；比较上周/上月对应已过部分。近3/6个月按日历月与此前等长周期比较，保持单次查询尺度。日数据不以周数据补造，缺失/零基期/未完成日保持未知。已有日查询和年度历史已覆盖所需区间，不增加并行Google HTTP调用。
- 社媒：按真实发布时间和北京时间分别统计四周期内已采集内容条数；不是全站内容总量、站内搜索量或Google相对热度。显示的百分比为两次真实快照共同内容ID的累计播放量增长，相较周期起始日期的已存快照；不是前期环比。显示共同样本数、实际起点时间，第一天不计算涨幅。缺少起点快照、播放量缺失或基期为0不补造；计数下降作为平台回调，不生成负热度结论。这个统计描述采集样本的整体传播，包含周期开始前已发布内容。
- 每个周期保留实际起止日期和采集时间。新周期未采完时保留上次成功值并标“上次”，不把旧值当成本次数据；失败保留已存结果。未提供有效发布时间的内容单独计数，不按抓取日期充当发布时间。采集时间、覆盖与涨跌口径在提示中可见。
- TK：`/v1/tiktok/search/keyword`分别this-week、this-month、last-3-months、last-6-months，按date-posted排序，兼容平铺和aweme_info嵌套结果。去重，不把region访问出口当作者或受众国家。
- INS：`/v2/instagram/reels/search`分别last-week、last-month、last-year；年度索引结果依实际发布时间分出近3/6个月。本接口仅Google索引Reels；索引窗口不等于发布时间，不能保证历史完整性。每页固定收费风险按实际响应记录。
- FB：`/v1/facebook/search/videos`一次公开原生视频/Reels搜索，各周期按实际发布时间分组；接口无日期过滤，不承诺完整历史，也不包含一般图文全量搜索。
- INS/FB查询附国家名称作为提示，不证明地域。三平台采样数量受返回排名、可见性、分页、预算、日期缺失和限流影响；不同平台数值不直接比较绝对需求。

## 持久化、额度与并发

复用现有加密ScrapeCreators配置，仅在即将请求时解密；不新增密钥页，不把Key返回前端或写日志。前端浏览、30秒刷新只读本地摘要，不触发外部采集。

独占`workspace_documents`的`keyword-trends:`命名空间：plan、run:北京时间日期、scheduled:日期、request:日期:步骤、snapshot:关键词hash:来源:日期、summary:关键词hash:来源、gate:日期。每日快照持续保存，无自动过期；不声称可从累计互动回补历史播放曲线。研究关键词和原公共内容收藏、关联均不被覆写，无数据库结构迁移。

通过现有competitor-runner锁串行执行，每轮最多一个社媒请求。动作保存/提交同样取得该锁；维护/发布原有竞品空闲锁已覆盖，不新增部署锁。`runCompetitorQueue`在现有竞品tick之后调用新tick。Google通过原`submitKeywordJob`稳定requestId进入原队列，沿用keyword-submit、普通runner、trend-runner和全局限流门，禁止单独并行直抓。

外部调用前持久化started请求记录，记录数即当日尝试/预留次数。数据、完成日志与扣费未知停止门在同一事务提交。崩溃后发现started记录，不重放；401/403/429、请求/保存结果未知停止当天共享社媒渠道。缺少明确credits_charged时保存有效数据，同时停止后续社媒调用并提示核对账单；未知不记为0。分页最多5页（INS接口文档最多11页，当前更严格）；每页归一化最多250条，超出会截断，不宣称采样完整。

## 验证与交付边界

- 后台专项覆盖参数、日历边界、TK嵌套结构、去重、零与缺失、真实共同快照、事务失败/重启、每日预算、暂停、权限、身份校验、分页和未知收费停止；前端专项验证周/月同期与3/6月及缺失数据。
- `keyword-trends.integration.mjs`挂入现有竞品隔离SQL夹具，验证数据库持久化、预算与幂等、研究员只读/管理员提交、完整名单校验、Google真实排队适配；兼容现有PostgreSQL/MySQL适配器。测试调用全部为合成响应。
- `tests/keyword-trends-ui.qa.mjs`针对独立`.artifacts/web-dist`生产包，使用本机合成接口与Chrome，禁止外部网络；检查双列表四列/四周期、0/缺失、实际提交条件、每日时间、读取失败保留、窄屏和研究员只读。
- 官方参数依据（2026-10-21公开文档）：https://docs.scrapecreators.com/openapi.json 、https://docs.scrapecreators.com/v1/tiktok/search/keyword/ 、https://docs.scrapecreators.com/v2/instagram/reels/search/ 、https://docs.scrapecreators.com/v1/facebook/search/videos/ 。真实账户权限、目标词覆盖与扣费未通过收费调用验证。
- 本功能不自行合并testing、推共享分支或部署正式；上线与启用计划由独立集成发布流程及管理员实际操作完成。
