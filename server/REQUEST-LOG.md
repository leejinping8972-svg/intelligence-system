# 请求频率日志

请求频率日志复用现有来源账本、`research_requests` 请求台账和定时监控请求账本，记录每次已接入来源调用的脱敏请求元数据，不保存查询参数、Cookie、Token 或响应正文。

管理员可在“资源消耗”页面查看“请求频率日志”，按时间、来源 ID、目标主机、任务/编号/环节或结果筛选。日志包含：

- 任务、任务编号、来源、市场和环节；
- 目标主机和路径（URL 查询参数已移除）；
- 开始时间、结束时间、耗时、尝试次数和是否重试；
- HTTP 状态、429、`Retry-After`、限流剩余值和失败类型；
- 按任务、来源和主机汇总的请求数、每小时频率、429 数和平均耗时。

查询默认展示近 7 天，复用消耗看板的完整记账快照，再按时间、来源、任务和主机筛选及分页。不再为每次翻页额外扫描三份原始账本，也不再因先截取最近5000条而遗漏更早的匹配请求。历史没有请求元数据的旧账本不会被补造为请求记录。

快照默认复用30秒；到期或主动刷新时共享一次后台更新，同时保留已有明细并标明实际快照时间。没有任何可用快照时沿用2秒有界等待与轮询，不用零条冒充未读完。离开页面停止轮询，快速更换筛选时忽略较早的响应。

请求开始前先写入 `started` 记录，完成或失败时更新同一事件。进程中断留下的 `started` 状态保留为进行中，不能据此推断上游请求已成功；未知结果仍按现有任务恢复规则处理。

请求日志只读接口为管理员动作 `server_source_request_log`。它不触发来源请求、余额查询、任务重放或额度扣费。
