# 情报总览每周数据汇总

位于概念监控看板之后。北京时间自然周（周一至周日），倒序分页，随总览市场筛选。至少展示最近12周，保留更早有首次发现记录的周及中间空周。本周持续累计，显示实际快照时间及索引更新状态。

- 新发现产品 / 广告：使用有效的 `discovery.firstSeenAt`，其次 `firstSeenAt`，按首次发现周归属。同类记录按保存的ID计数，重复抓取不重复累计；不使用最近抓取日期冒充首次发现。演示记录、无效或未来日期不计入。
- 新品 / 新广告：是该周新发现记录中的子集。按首次抓取时已上架 / 开始投放不超过7天判断，日期按北京时间比较（日期差0～7天，含第7天）；历史周不会随着今天的时间推移失去新品资格。产品需已在现有新品池内，沿用现有来源上架证据规则，包含新品池明确标注的TikTok曝光替代口径；广告使用现有来源投放证据规则。缺日期、来源依据或首次发现日期时不推测。非新品池产品及历史宽窗口入池但首次发现时已超过7天的产品，仅计入新发现。
- 周统计代表当前保存记录的发现历史，不能还原已删除记录或丢失的首次发现资料；后续补齐或修正来源日期可能修正历史汇总。首次发现日期与来源上架 / 投放日期分别保留，不能相互替代。

新增独立 `weekly-summary-domain.mjs`、`weekly-summary.mjs`，复用 `workspace_statistic_rows` 的 `kind=weekly-summary` 和独立文档标记 `read:weekly-summary-version`。无schema、迁移、依赖或全局读模型版本升级。后台沿用workspace-reads互斥锁，从已提交紧凑投影每批200条流式累计，仅保留每周计数，不持有全部商品或广告。所有市场、数据及元数据同事务发布；失败回滚、60秒后重试，保留旧汇总。

首次、北京时间跨日及索引追平后生成快照；其余索引版本变化时每5分钟补充。未发生数据变化不重复扫描。页面刷新及轮询仅通过现有 `server_workspace_statistics` 读取持久结果，接口不进行来源聚合或发起采集。分页参数有界、单页最多100周，市场白名单；只在后台工作器取得已有锁后生成，不要求全局索引队列清空。

验证：`node --test server/weekly-summary.test.mjs server/workspace-reads.test.mjs`，覆盖7天边界、首次发现周与上架周不同、重复抓取、跨周跨年、北京时间与宿主时区、缺失 / 未来日期、市场隔离、持久快照分页与只读接口、后台节流与跨日更新、失败回滚及统一API分派。全部为合成数据及隔离PGlite，无正式数据库或收费请求。
