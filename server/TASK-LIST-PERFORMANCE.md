# 任务去重、列表同步与监控视图交付

基线：`c9f17fa2e4d20743d853103d040eee5677032acd`（已确认的 testing）。分支：`codex/task-list-performance-20261020`。本功能未部署、未修改共享 testing。

## 行为与原因

- 旧接口按市场映射同一后台 job，而每张卡片使用全任务进度，产生重复展示。现在按 `cloudJobId` 合并，列出覆盖市场；不同 job、历史任务保留原记录。没有取消或删除历史正在执行的任务。
- 默认紧凑列表，可切换卡片并记住视图；支持多个状态同时筛选、任务名称/编号搜索、10/20/50/100 条分页。等待重试单独显示，详情保留完整日志与逐词结果。
- 相同种子词、市场、渠道、深度、数量/预算、补齐名单的进行中关键词任务会被复用。客户端并发调用共享提交结果，服务端以数据库连接级锁串行检查请求编号和语义重复。终态历史不妨碍主动新建下一轮任务。

## 接口与兼容

- 新增认证读动作 `server_workspace_delta`：客户端携带上次 `revisions`，按业务文档、关键词、任务三个通道返回变化的数据。未变化的通道省略，空数组表示已清空。旧 snapshot 动作保留；非服务器模式继续使用原动作并行读取。
- 新增认证读动作 `server_task_detail`，按 job ID 读取完整进度与日志。列表仅返回摘要；详情仅打开时及任务版本变化时刷新。读动作不延长空闲登录会话。
- 文档使用现有 revision；关键词/任务使用身份、时间、状态与数据库内容校验和，避免现有 `now()` 秒精度造成漏更新。校验和只用于变化检测，不承担安全校验。SQL 包含 PostgreSQL/MySQL 两种表达式。
- 并发页面刷新共享同一 Promise，关键词按 Map 合并。应用远端快照时暂停本地同步侦测，避免逐条深度序列化；保留请求期间的本地待保存修改。失败不推进客户端版本。
- 活跃任务每 5 秒同步，空闲最多每 30 秒，隐藏页面暂停定时读取；后台任务仍由服务器执行。

## 集成与发布注意

- 前后端需要一起集成；旧 API 不支持新 delta/detail 动作。本任务没有推送、合并或部署权限。
- 新增提交锁：MySQL `intelligence:keyword-submit`；PostgreSQL advisory lock `89761032`。发布排空/冻结提交的守护逻辑须一并纳入此锁。未改任务 checkpoint 格式或迁移数据库结构。
- 三个变化通道仍是整通道传输；首屏仍读取现有业务集合、最多 10000 个关键词和最近 200 个任务。本次不宣称已经为所有业务列表实施服务端分页。校验和仍有数据库读取与计算开销，大数据量后续应增加专用版本计数与分表分页。
- 未测量正式环境延迟，不承诺具体提速倍数。本次未连接正式数据库、未触发真实采集或收费工具。
