# 关键词周期趋势对比

关键词研究和已入选关键词使用同一组件/纯计算模块显示：`近30天：78(+3%)`、近半年、近一年，保留一年曲线入口。趋势详情、任务进度、导入、评分和雷达引用统一30天口径。原始28天增长值不会直接换名使用。

## 口径

- 数字是Google Trends原始查询尺度0–100的平均相对热度，按实际覆盖日数加权、显示整数；不是搜索次数。百分比为 `(当期均值-前期均值)/前期均值 × 100`，一位小数。两期必须来自同一次查询的同一尺度，不拼接/各自重新归一化。
- 30天：最近30个完整UTC日，对此前30日，必须有日期完整的日数据。半年/一年：6/12个日历月，对此前6/12个月；月末和闰年按UTC日历计算。时段以该源最新完整数据为截止，悬浮提示显示日期；不把历史采集当实时。
- 周时点按真实日期覆盖日数加权，不把一个周点当一天。允许查询边界最多一周的截断，不填补内部缺失周；日时序不允许缺日。部分时点、无效数值/日期被排除，排序和同日去重。
- 当期缺失显示待补数据；当期有值而前期缺失显示待补对比；前期0显示基期为0，不显示无穷大或假0%。不同国家、查询批次不能据此比较绝对需求；Google网页重新采样、选择范围或粒度不同也可能造成数值差异。

## 采集与兼容

新提交研究任务经validateJob固定`trendComparisonVersion:2`。沿用原annual/daily两个阶段与日记键；annual单次查询约两年+8天覆盖边界，保存完整trendHistoryPoints及来源/粒度/采集时间，一年曲线只保留最近约一年。daily仍查近3个月，以提供两个完整30日窗口；不增加第三个阶段或外部收费来源。

已运行/保存任务没有新标记时，annual继续原today12-m范围、原队列和已完成步骤；不自动升级、重跑或补采。新建“补齐数据”任务可为旧一年记录补两年历史；未补之前年度涨跌保持未知。重启继续复用原请求账本与成功阶段。直接更新趋势入口同样保留两年历史。现有评分权重不变，短期动量从28改30天，模型版本升为keyword-research-v3.1-30d。

新字段均为现有JSON中的可选字段，无数据库结构迁移；domain清洗保留历史字段，Docker模型构建已复制新计算模块，collector/model构建产物同步。导入只按明确日期/粒度计算，缺失不臆造；雷达先从原始日期重算30天再引用，避免旧增长值混用。

合成时序覆盖30日与旧28日区别、半年/年度前期、闰日/月末、零基期、缺日/缺周、部分点/无效点、重复与乱序、前后端一致及旧年度缺失。队列测试验证旧任务不升级、2年历史一次获取与持久化、恢复不重抓annual；原限流/重试/取消回归继续通过。CI新增专项与collector构建。
