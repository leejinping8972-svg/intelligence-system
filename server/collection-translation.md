# 采集流程内翻译

本功能基于 testing `3e0fde9d93a4b2862d02f2488250770956a93785` 开发。沿用已配置的分析模型，不接入新翻译供应商。

## 流程

来源响应先写入现有请求账本，再等待翻译完成，之后保存业务记录和推进采集步骤。翻译失败会让该步骤保持未完成，已成功的来源响应不会改成失败或重新采集。重启后复用来源响应及翻译缓存；结果未知的模型请求不自动重试。

统一服务为 `server/collection-translation.mjs`，字段规划、原文指纹、分段和校验位于 `server/collection-translation-domain.mjs`。短提示词仅执行翻译，批内去重，每批最多 32 项、2400 字符；长文本按 Unicode 字符分段，原文完整保留。相同文本跨字段复用持久缓存，进程内并发请求共享在途结果。缓存请求归属在调用前提交，不持有业务事务等待模型。模型消耗纳入现有资源消耗记录。关键词和相关查询继续使用管理员配置的关键词术语规则，输出约定由统一服务约束。

## 节点核查

| 节点 | 处理 |
| --- | --- |
| 关键词及种子词 | 采集返回和保存入口统一补齐 `termZh`、`seedTermZh`；词与种子相同时共用译文；合并时保持种子与译文配对。 |
| 热门、上升相关查询 | 随趋势结果保存 `queryZh`，列表和详情直接读取。 |
| 广告 | 采集阶段翻译品牌、标题、文案及可用原文字段；更新原文时更新机器译文与自动生成的卖点；保留人工译名。 |
| 商品 | 来源结果、入库及详情/AI字段提取后的缺译字段均使用统一服务；平台、资源发现、上新监控及独立站商品采集共用。合并保留旧原文时，同时保留对应旧译文。 |
| 独立站 | 采集、合并与手动添加入口补齐品牌、类别、介绍和主要产品；已有站点新增产品时更新整组译文；列表和详情中文优先。 |
| 竞品和热词监控 | 在业务写入事务前翻译观察结果、衍生关键词与热词种子，之后原子保存。 |
| 来源字段分析 | 复用采集译文，并在保存新提取字段前补译遗漏项；仍属于原采集任务的分析阶段。 |
| 手动关键词中文名 | 显式修订工具保留，复用统一服务、缓存、用量和未知请求保护；不会由浏览触发。 |
| 公共内容 | 原有标题翻译/摘要已在采集任务结束前执行，无页面打开后自动补译请求；保留既有可选整理开关和最多 10 条摘要样本规则。 |
| 画像研究入库、离线导入 | 画像使用已有中文主题展示名，离线迁移保存已有数据；这些入口不因本功能增加模型调用。 |
| 历史补译脚本 | 仅显式运维工具，不接入页面浏览，本次未执行。旧关键词译文缓存可在后续采集时直接复用。 |

关键词页面已移除 `server_keyword_translations` 自动请求及单独的“翻译中”状态。历史缺译记录显示“中文待补齐”，不以浏览行为触发付费回填。
