# 商品分析与后续翻译失败

商品采集先取得来源资料，再保存有请求账本的字段/健康分类分析，最后翻译新增字段。后续翻译校验失败或结果未确认时，不能把已经成功的字段分析改回 pending，也不能丢弃有效的中文字段、分类和原文引用。

`prepareProductIntake` 对翻译单独记录 `翻译：…` 异常，仍返回已完成的 analysis。只有字段分析本身失败时才保持 pending。命中有效分析缓存后也采用相同处理，不新发字段分析请求。健康新品仍须通过原有分类、上架时间、正销量和条件类目规则；翻译缺口使任务保持 partial，但不会单独制造 health_analysis_missing 候选。

`runSourceFields` 对已完成商品 intake 的结果不再次调用翻译。有效分析及字段在原有事务、取消和指纹检查下保存，翻译异常继续写入日志，任务仍是 partial。广告、网站及旧商品分析路径沿用原翻译流程。

这项修复不把日销量接口不支持、卖家空返回、缺少有效用途引用或最新销量为 0 改记为成功，也不会启动历史任务、修改定时配置或自动发起来源/模型调用。商品监控的页面进度可包含商品观察及后续 AI 分析，走完进度不表示每个指标均已取得。

历史误置候选的分类响应若已保存在 research_requests 中，可在获准恢复该任务时复用。应限定原任务与商品，核对请求已确认、来源身份/指纹、原上架窗口和当前正销量证据；保留翻译缺口、未知请求保护和历史记录。不能直接将整个任务标为 completed，不能因存在旧正销量而覆盖较新明确的 0。本修复不包含生产恢复或数据库迁移。

合成回归 `product-intake-translation.test.mjs` 覆盖有效分类保留、缓存及未知翻译、字段请求未知、健康新品实际入库但任务保持 partial，以及 PGlite 中商品 worker 的落库、单次翻译、收藏及原分类保留。
