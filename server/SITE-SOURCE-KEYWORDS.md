# 独立站来源关键词回退

Semrush 竞品拓展只提供来源域名、没有实际检索词时，复用同市场来源站点已经保存的关键词关联。保留 `sourceEvidence` 原文、已有人工关联，并在 `sourceKeywordLinks` 中记录来源域名、站点编号、关键词编号和原词。该记录表示来源站点的关键词，不能作为具体广告重叠词的证据。

只读取现有站点和关键词，不发起 Semrush、模型或其他采集请求。仅继承一层，来源站点自己继承的词不继续向外传递。来源档案或关键词缺失时保存空来源记录，界面明确显示暂无已记录关键词；不创建虚构关键词。后续该目标站点重新保存时，会再次从已有来源资料补取。已有实际检索词的站点保留实际词。

## 写入与启动影响

- `mergeBusiness` 保存站点时，在同一事务中补充来源关键词及关键词的反向 `siteIds`；关键词先锁定并重新读取，合并保留其他关联。
- `store.mjs` 在原 `workspace-reads` 互斥下执行一次历史补齐，完成标记为 `read:site-source-keywords-v1`。只改有来源证据的站点的 `keywordIds/sourceKeywordLinks`、相关关键词的 `siteIds` 和派生索引失效记录，无 schema 变更。
- **包含启动业务数据补齐。集成发布须识别这项影响，准备对应站点/关键词和完成标记的恢复快照，不能按“无数据迁移”处理。** 当前功能开发没有连接或写入正式数据库，也没有部署执行该步骤。
- 补齐幂等；已有检索来源纠正完成标记与记录保留。列表投影包含来源标记，既有关键词筛选、计数和导出复用双向关联。

## 点击筛选

列表和详情中的来源域名使用 `/sites?sourceSite=<domain>`，在当前站点市场中按完整域名匹配。允许 `www` 别名，排除仅包含相同文本的其他域名。列表入口清除关键词、日期、评分等旧条件，分页与选择复位；“清除站点筛选”移除此条件。服务端的列表、全选及导出选择共用 `siteDomain` 条件。

## 开发验证

`node --test server/site-source-keywords.test.mjs server/site-keyword-provenance.test.mjs server/keyword-associations.test.mjs`

覆盖同市场继承、循环阻断、真实检索词保留、缺失来源、重复证据、双向持久化、幂等、原始证据/人工关联保留、域名精确筛选、关键词选项和导出选择。另做完整 Web 类型检查、独立开发构建和本地真实 Vue 组件交互验收；未做正式账号验收或独立 MySQL 验证。
