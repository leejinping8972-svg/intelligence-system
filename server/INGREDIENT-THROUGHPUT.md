# 成分风向吞吐与进度优化

功能基线：`39253c1d2abed066e58a67bfb993c2fd0306e86d`。本次是功能开发交付，不包含正式部署或任务补跑。

1. 评论按页归档。`ingredient-trend-documents.mjs` 使用专用连接事务、按名称排序加锁读取和批量 upsert；保留正文、首次发现时间、内容版本和确定性的观测键。每批最多 150 个文档、约 512KB JSON（单个超大文档单独提交）。限制批量写入 `ingredient-trend:` 命名空间。评论状态准备和分析资料准备中的每帖读取也改为批读。
2. 普通队列中的四类计划扫描，在一次扫描完成后间隔 30 秒再次执行；保持原 runner 锁、每轮执行一个任务一步的公平性。分析首次发现同监控采集尚未结束时保存依赖 ID，之后由 runnable SQL 排除。采集完成、部分完成、失败或取消后自动恢复资格，分析重新检查依赖，不依靠等待任务定时写检查点。计划触发最多增加约 30 秒的扫描等待，仍受当前任务步骤耗时影响。
3. 评论 v2 检查点仅保存每帖摘要和不可变状态引用，一次载入选中帖子。分析资料按 80 条分块，原每批最多 40 条、40,000 字符的规则保留；分析中间结果也保存为不可变文档，内容未变时不重复写入。旧检查点在原任务下一次执行时转换，不修改任务输入、来源步骤编号、分析偏移、数量上限或请求账本。先写引用内容，再提交检查点；崩溃恢复仍读取旧引用，并复用原步骤的已保存响应。
4. 列表、卡片和详情显示当前阶段、帖子、新入库帖子、评论、回访/待续/异常帖子、页数、来源请求和模型请求。未知分母与依赖等待不生成百分比；运行中最高 99%。分析依赖显示“等待采集”，底层任务状态与筛选语义保持兼容。

最近耗时的口径：

| 字段 | 含义 |
| --- | --- |
| `lastSourceMs` | 本次 `collect` 调用的用时，包括账本处理、缓存响应读取或真实来源/模型调用；不包含此前保存检查点 |
| `lastProviderMs` | 来源回执提供的时间，没有回执时为空；缓存响应可能携带原请求时间 |
| `lastArchiveMs` | v2 评论页批量归档、游标状态、帖子摘要及不可变样本状态保存的合计时间 |
| `lastCheckpointMs` | 最近一次已完成的检查点保存时间，于下次保存时带出；首次保存无此值，进程重启后重新积累 |
| `lastQueueMs` | 本轮启动时刻减去上一检查点的 `nextRunAt`，即“续跑延迟”；可能包含上一保存提交、其他任务轮次和计划扫描的影响 |
| `lastSchedulingMs` | 本轮领取任务前四类计划扫描用时；本轮跳过扫描则为 0 |

以上项目不是互斥分段，不能相加推断完整页间时间；没有为了记录耗时增加单独检查点写入。
