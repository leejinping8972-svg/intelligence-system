# 概念监控看板

工作台在资产概况下展示概念监控看板；已入选关键词在关键词名称后显示采集批次。看板支持批次搜索、市场筛选、分页，以及所有字段双向排序，默认按采集时间倒序，缺失时间放末尾。

## 统计口径

- 批次入口为当前关键词 `batch` 与广告 `collectionBatches` 的并集，排除空白及演示数据；相同批次名称归入同一行，广告专有批次也保留。不会凭关键词相似度或域名猜测历史批次。
- 按已有 ID 关系关联关键词、广告、独立站、商品：关键词正反向关系、广告的关键词/商品/站点关系、站点下的商品及广告。每一步校验市场，同一批次同一类型按 ID 去重；共享站点不会反向扩散到其他批次的关键词。失效 ID 不计数。同一记录可关联多个批次，各批次独立计数。
- 今日新增以汇总日的北京时间日期为准，优先取 `discovery.firstSeenAt`、`firstSeenAt`；独立站其次取最早已保存来源证据日期，其余缺少首次日期的历史记录使用现有采集时间。无有效日期不计入今日新增，不将广告投放日期/商品上架日期当作新增日期。
- 采集时间为该批次关联记录最近一次有效采集时间。汇总日期和生成时间会一起显示；跨午夜或汇总失败时保留旧结果及其实际日期。
- 现有关键词只保留当前批次；已被旧写入覆盖且未在广告中留存的历史批次无法还原。

## 持久化与性能

复用现有 `workspace_statistic_rows` 存储 `kind=concept-monitor` 的各市场汇总，`workspace_documents` 仅保存元数据及独立版本标记，无新增表、结构迁移、依赖或全量读模型版本升级。

后台读模型工作器使用既有 `workspace-reads` 锁和独立事务，从当前已提交的索引生成首份汇总，无需等待全局索引队列清空。每日北京时间 09:00 到期的汇总也独立执行，避免被每小时全量索引校准反复推迟。

生成时队列仍有待办，会在存表元数据标记 `indexing=true`，页面展示现有结果及“后台数据更新中，汇总每 5 分钟自动补充”。只要索引发布版本继续推进，后台每 5 分钟补充一次；队列追平后，在下一次调度检查（最多约 1 分钟）生成完整快照并恢复每日 09:00 更新。没有索引版本变化时不重复扫描；空的初始索引会明确提示后台更新中。页面“刷新”和自动轮询仅读存表，不触发生成。

从紧凑投影每次读 200 条，分批写入，所有市场与元数据同事务发布。失败回滚并保留上一份结果；重启依据持久的版本、索引发布版本、时间和更新状态判断。仅升级概念汇总自身的版本标记，不提升全局读模型版本、不重建全局索引，无采集重放或外部来源/模型请求。

现有 `server_workspace_statistics` 增加 `kind=concept-monitor` 分派，API 仅对汇总表进行筛选、排序、计数和分页，不读原始业务文档或实时聚合关系。排序字段白名单，数值按数字排序且先排序后分页；单页最多100行。页面“刷新”只重新读取已存汇总。

## 验证

`node --test server/concept-monitor.test.mjs server/workspace-reads.test.mjs server/workspace-statistics.test.mjs`：合成关系/去重/市场/北京时间边界，PGlite 持久汇总、235个关键词跨批读取、分页前排序、搜索转义、重启日更新与发布失败回滚、读接口无源扫描；现有读模型专项同时验证统一API分派。既有 `workspace-reads.integration.mjs` 在 MySQL CI 中复用同一读模型专项（实际执行情况见交付记录）。

无正式业务数据或数据库连接，无来源/模型收费调用。

## 批次跳转与合并

8个数量字段均可跳转到关键词、广告、独立站或商品列表，携带精确批次与当前市场；今日新增携带本次汇总的北京时间日期。商品跳转包含商品库和新品池。进入时清除旧的搜索/分类/评分/收藏等限制，显示可清除的批次筛选，翻页、排序、导出及全量筛选选择沿用服务端筛选。切换市场清除旧批次深链约束，浏览器前进/后退可恢复。

汇总后台同一事务保存各市场、批次、类型的全部ID与当日新增ID（`read:concept-members:*`，批次名以SHA256作为键），名单与数量来自同一关系遍历。列表用已存名单筛选，不实时重新聚合关系。名单只保留最新快照，过期日期深链不冒充当日结果。独立概念版本升级v3，全局v8不变，无新增表或结构迁移。

管理员可多选2～50个批次，选择已有目标或输入100字以内的新名称，确认后统一所有市场的同名批次。服务端再次校验权限、快照中批次存在性及批次归属版本；使用原workspace-reads互斥与单事务，批量改写当前关键词batch和广告collectionBatches，保留其余字段/日期/关联ID，不删除业务资料，不合并或重跑采集任务。共享关联去重后重新存表，不简单相加计数。

`settings:collection-batches`保存规范批次映射及合并人/时间/源名称/目标/实际修改数量，用作持续有效的批次归属：旧任务检查点晚到、尚未进入索引的记录和后续原批次写入都会在投影、详情及新汇总中归入目标，不能重新出现源批次；原任务/账本/原始响应与采集历史保留。再次合并扁平化映射防循环。并发/重复提交使用expectedRevision拒绝，失败回滚归属/记录/刷新标记。提交后后台最多约1分钟开始更新，看板继续展示存表结果；接口不现场生成汇总。
