# 重点监控批量操作与月搜索量排序

重点监控的独立站、广告主支持跨全部筛选分页选择。管理员可批量设置每日更新时间、每渠道页面上限、启停状态；仅修改弹窗中勾选的设置。批量暂停清除待执行标记，当前请求自然结束后停止后续采集。旧商品监控仍使用原来的逐项入口。

批量取消监控保留已采集商品、观察历史、去重记录与请求账本。正在执行的监控不会被移除，会提示先暂停并等待请求结束。接口返回成功 ID 和逐项失败原因；页面清除成功项的选择，保留失败项供处理和重试。输入和权限校验在写入前完成，持有原有监控配置锁，数据库写入异常时整批回滚。最多处理 100 个对象，与现有监控容量一致。

关键词库和已入选关键词的月搜索量均支持升序、降序。服务端在全部筛选结果上排序后分页，相同数值按 ID 稳定排序；本地模式也支持排序。排序与展示使用同一口径：当前词自身市场的非负数值估算，真实 0 正常参与排序；未知、字符串、负值和其他市场的估算均放在末尾。

无数据库结构、迁移、依赖或读模型版本变更。排序仅增加现有列表查询的 ORDER BY 表达式，不触发采集或模型调用。

验证入口：`server/monitor-bulk.test.mjs` 覆盖实际管理员动作和隔离 PGlite 事务；`server/workspace-reads.test.mjs` 覆盖跨页、入选过滤及双向排序；`tests/use-core-list.test.ts` 和 `tests/keyword-volume-column.test.ts` 覆盖两个列表列定义与本地排序。
