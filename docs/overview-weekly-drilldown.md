# 批次本周统计与每周汇总筛选

概念监控看板在今日统计后增加本周新增关键词、广告、独立站、商品四列，可排序并点击查看相应名单。北京时间周一至周日，按已保存关联内的首次发现时间计入本周；缺少首次时间时沿用看板原有采集时间替代规则。每个批次内按资源 ID 去重，多个批次有同一资源时各自计数，因此不能将批次数量相加当作全局去重数量。今日统计及原有批次合并行为保留。

独立概念快照从 v3 升至 v4，包含 `weekStart`、`weekEnd` 及四项 `*Week` 计数。原有 `read:concept-members:*` 文档补充 `weekIds` 和 `weekStart`，与快照同事务发布。批次链接携带 `conceptBatch`、`conceptWeek`、`market`；列表只匹配对应市场、批次、统计周的存表名单。过期批次周链接返回空，不退化为无筛选列表。周一零点后的后台更新立即换周，无需等到当日 09:00；其余保持既有每日和索引追平调度。

下方每周数据汇总默认折叠，折叠时不读取或轮询周统计。展开后沿用原有分页、市场切换、刷新和背景更新。四类数字（包含 0）可以跳转到商品或广告列表。链接带 `summaryWeek`、`summaryNew=0/1`、`market`，列表显示可清除的周统计筛选提示，并清除已有搜索、日期、产品池及当前新品状态等旧筛选；商品展示两个池内匹配的记录。

周汇总口径保持不变：产品/广告按首次发现日期归周，新品/新广告是其中首次抓取时来源日期不超过 7 天的记录，产品还须属于新品池。历史周使用首次抓取时的资格，不使用今天的移动新品筛选。独立周快照从 v1 升至 v2，同时发布 `read:weekly-members:<market>:<week>:<collection>` 文档的 `ids` / `newIds`，让列表、分页、全选和导出使用同一范围。旧 v1 快照过渡期间保留原数字，名单更新前不启用跳转。后续来源修正/删除会反映在下一次快照中。

所有名单由既有后台读模型事务更新；列表请求不临时聚合、不重建名单、不触发采集。MySQL JSON_TABLE 结果保持 `utf8mb4_bin` 精确 ID 比较，避免排序规则不匹配。无表结构、迁移、依赖、全局读模型版本、来源采集或任务队列变更。

验证覆盖上海周边界、重复关联、未来时间、市场隔离、四类周指标与实际列表一致、历史新品资格、发布失败回滚、周一零点切换、参数校验，以及桌面/手机默认折叠、展开、点击跳转和筛选清除。
